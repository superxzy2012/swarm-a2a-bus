# 蜂群真实@治理机制 v1

- 治理方：Muse（BOSS 2026-11-10 20:57 语音派单）
- 配套文件：《蜂群真实@标准与教程-v1》《蜂群真实@验收测试规程与记分表-v1》
- 版本：v1（2026-11-10）

---

## 1. 治理对象与违规定义

治理对象：蜂群全体成员在管理群及蜂群工作群中的@行为。

违规（记一次「假@事件」）须同时满足：
1. 消息声称或暗示已通知/已@某成员（如正文「@某某 请处理」、回执中写「已@通知」）；
2. 经 API 核查，该消息 mentions 数组为空或不含其所称目标成员的 open_id；
3. 且未按教程 5.3 路线注明「群内仅为礼节提示，正式件见总线」。

纯聊天中随口提到名字、不构成通知声称的，不算违规。查不到原消息或 mentions 无法核验的，记 UNKNOWN，不算违规、不下结论。

## 2. 巡检方式

- 依托现有 muse-feishu-inbox-watch（每 5 分钟拉管理群全量历史 API 核查）：在既有筛查之外，顺带核查声称已@的工单/回执类消息的 mentions 字段。
- 巡检静默：无违规不发任何消息（遵守 BOSS 2026-11-08 全蜂群巡检静默令）；发现违规按第 3 节阶梯处置，处置动作本身即为留痕。
- 每起假@事件记录：日期时间、成员、message_id、所称目标、mentions 实测结果、处置阶梯、结果。记录随记分表同目录留档。

## 3. 处置阶梯（三级）

### 第一级：当场提醒（首次及偶发）
- 在群里以真@回该成员一条简短提醒（或经小林代发），并附教程链接/位置。
- 话术模板：
> @<成员> 你 <时间> 那条（<message_id>）是纯文本@，没有@实体，对方不会被唤醒。请按《蜂群真实@标准与教程 v1》改发真@版，并注明旧条作废；发不出真@的请走小林代发或总线文件通道。本提醒由 Muse 巡检发出。
- 只提醒事实与改法，不指责、不扩散到其他群。

### 第二级：通报 QUEEN（同成员 7 天内再犯，或首次后 48 小时未改发）
- 经总线向 QUEEN（星期五）落通报文件，并在群里真@QUEEN 一条简报。
- 话术模板：
> @星期五 通报：<成员> 于 <日期> 再次出现假@冒充送达（证据 message_id：<id>；首次提醒时间：<时间>）。请 QUEEN 督促其按教程整改并完成验收测试，整改结果请回执本通报。——Muse 治理巡检
- 同步把事件记入该成员治理台账，等 QUEEN 回执。

### 第三级：报 BOSS（通报后仍不改，或造成工单延误等实际后果）
- 在主对话向 BOSS 报告：成员、全部证据 message_id、已走完的提醒与通报记录、造成的实际影响（如有）。
- 话术模板（对 BOSS）：
> BOSS，真@治理升级报告：<成员> 假@事件共 <N> 起（证据：<message_id 列表>），已提醒（<时间>）、已通报 QUEEN（<时间/回执情况>），仍未整改 / 已造成 <具体延误>。请您定夺处置。
- 报 BOSS 后停手等指示，不自行采取进一步动作（不踢人、不停权、不代发其全部消息）。

## 4. 正向口径

- 成员完成验收测试通过/路线通过的，在记分表更新并在周汇总中点名确认（只报事实，不发奖状式刷屏）。
- 代发链路（小林枢纽）若出现积压或代发失败，Muse 先报 QUEEN 协调，不等到假@事件发生。

## 5. 边界

- 本机制只治理「@的真假与送达声称」，不评价消息内容对错；内容问题走原有总线/QUEEN 流程。
- 一切判定以 API mentions 实测为准；拿不到证据就写 UNKNOWN，不推定、不冤枉。
- 任何处置消息不得包含任何应用凭据或 token。
